# Persistence and navigation

Mandatory contract from the [Angouri working guidance](../../AGENTS.md) whenever a change affects loading, unsaved-work protection, imports and links, the saved-recipe library, Restart or progress reset. Code paths are repository-relative. Interactive changes also require [focus-keyboard](focus-keyboard.md) and [layout](layout.md); async startup or navigation changes also require [engine-recovery-performance](engine-recovery-performance.md).

## Product decisions

Keep Menu available during loading. Puzzles remains disabled until its actual chapter list is populated. Completing initial loading, including restoring saved progress or opening a deep link, preserves any menu page and deliberate focus opened meanwhile. Only an explicit navigation or import dismisses those dialogs. Dialog body scrollers reserve enough room for complete focus outlines and raised button edges on every side; check the recipe-name input and Save button at both edges of Save & open. Tab and Shift+Tab wrap directly between the first and last available dialog controls, skipping the page body and neutral dialog container. Preserve native order within those boundaries and include non-text inputs such as Skip animation under Safari's keyboard defaults.

Protect unsaved placed blocks when manually switching between puzzles, Create or saved recipes. Offer Save and continue, Discard, and Cancel. Saving must succeed before navigation; keep the recipe open on a storage failure. Preserve mode, source, targets, exact nodes, empty-slot layout and view in saved recipes. Opening one must not roll back global completion. Continue accepting earlier artifact-only library entries. The ordinary Next action after a completed puzzle stays one click. Create carries current blocks over; the prompt preserves the prior puzzle context. Create from the ending uses the same guarded transition as Create from the menu.

Validate imports before committing a workspace change. File imports and same-document links use the Save/Discard/Cancel guard after pending edits have settled, so an accepted late edit is protected. Encoded shared links carry only creations or challenges; authored level links select a puzzle. A link never has authority to replace global completion. Replacing the completion record belongs to explicit progress-file import or confirmed reset. Invalid links preserve a valid saved workspace and stay distinct from worker failure; obsolete startup/import work cannot replace a newer navigation or persist its URL. Export progress contains the current workspace and completions; named saved recipes and recovery copies remain on this device, and the interface must state that scope.

Save & open lists the recipe name above its context and saved local date/time: `Puzzle 1.5 · date and time`, `Create · date and time`, or `Shared challenge · date and time`. Keep the puzzle number next to Puzzle; the middle dot separates context from timestamp. Store a new save's timestamp in ISO format and render it in the visitor's locale. Do not invent dates for older saves; show Date unavailable. An old artifact-only creation is labelled Create because it does not retain an authored puzzle workspace.

Saved-recipe trash controls use the same red danger ink as resetting all progress, including a red-tinted hover state. Deleting removes a recipe from the active library and places it in Recently deleted with a named Undo action. Closing a menu is not confirmation. Recovery persists across menu navigation and reloads, with no timeout or automatic eviction. Store the removal and recovery copy in one atomic durable transaction, preserving the exact artifact, workspace, view and original save date. IndexedDB is authoritative for progress and the saved library: migrate each existing local-storage record once, retain its exact raw bytes, and use later local-storage writes only as a best-effort compatibility copy. A failed primary transaction must leave the durable record and live workspace intact; a failed compatibility copy must not turn a committed save into a reported failure. Do not fall back to unsafe local-storage mutations when IndexedDB is unavailable. Undo restores the saved entry without opening it or editing play; reveal and focus Undo after deletion, then reveal and focus its Open button after restoration. Recovery rows show the saved context and original save date. A full active library or storage failure must retain the recovery copy and show an actionable error. The twelve-item limit applies to active saves, not recoverable deletions. Continue reading old artifact-only entries.

Saved recipes have a Rename action beside Open. Edit the name in place, preserving the artifact, workspace, view and original saved timestamp. Enter saves; Cancel/Escape restores the old name and returns focus to Rename without closing Save & open. A failed storage write keeps the draft and original saved entry intact. Names remain plain text, trimmed and limited to 60 characters.

Library mutations identify entries by stable ID and reread the latest durable library inside one cross-tab read/modify/write transaction. Recheck the twelve-active-save limit at commit time, including after an asynchronous export. Preserve unknown entries, legacy records, exact recovery copies and existing entries beyond the active limit instead of truncating on read or write. Refresh library and completion displays on storage changes without replacing another tab's active construction, history or deliberate focus. If safe storage coordination or writing fails, retain the current data and report failure; never claim success for an unlocked stale overwrite. Recently deleted may be reclaimed only through an explicit, named permanent-delete confirmation; closing a menu, age and capacity do not authorize eviction.

Recently deleted may permanently remove one recipe only through its explicit Delete forever action and a confirmation naming that recipe and explaining that it cannot be undone. Cancel has default focus. A failed write retains the recovery copy with a retryable error. There is no timeout, automatic eviction, bulk purge, or implicit removal during import or progress reset.

Restart belongs beside Undo/Redo on the recipe and clears only that construction, with Undo available. Settings may reset all puzzle progress only after an explicit confirmation explaining that the current recipe and completions will clear while the saved library and preferences stay. Use "Import progress from file" and "Export progress" in Save & open, with arrows pointing into and out of the same tray. Merge newly earned completions against the latest stored record within its progress epoch. Confirmed reset and explicit progress-file replacement begin a new epoch so stale tabs cannot resurrect earlier completions; a genuinely new win after reset belongs to the new epoch. Persist the replacement successfully before clearing the current recipe, completion record or URL, and keep the confirmation open with an actionable error if storage fails.

Workspace navigation belongs to the latest deliberate intent from the moment it starts, including before a saved-library read. Check ownership after kernel and storage awaits and before delayed focus or URL changes. An obsolete continuation cannot dismiss a newer dialog, report a stale error, replace a newer workspace or restore an old URL. A reset that already committed remains durable if a newer navigation begins while its acknowledgement waits; supersession suppresses only its obsolete UI continuation.
