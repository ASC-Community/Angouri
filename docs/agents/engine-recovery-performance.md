# Engine, recovery and performance

Mandatory contract from the [Angouri working guidance](../../AGENTS.md) whenever a change affects the math worker, checkpoint evaluation cost, worker-epoch recovery or presentation caching. Code paths are repository-relative. Async startup or navigation changes also require [persistence-navigation](persistence-navigation.md); exactness rules are in [kernel-exactness](kernel-exactness.md).

## Combined progression and exact extensions

Profile the math worker separately from the main thread before blaming plot sampling for a slow edit. Compile a stage's AngouriMath numeric evaluator once and reuse its samples; retain exact symbolic evaluation at checkpoints. Reuse exact readings instead of simplifying each constant again for every displayed copy. A proved rational range can reject an impossible target (for example, sine stays between -1 and 1), but an approximate numeric value or a Signum result obtained through numerical evaluation is not an exact miss or hit. Keep full expression simplification and bounded caches separate from exact target validation. Segmented recipes reuse unchanged operation prefixes, exact readings, presentation and compiled evaluators in bounded context-aware caches. Exact rational quarter-turn and nested-sine landmark proofs may avoid expensive general simplification, but approximate samples must never decide a hit. Benchmark every operation, representative compositions, repeated sine and actual UI placements; report cold and warm costs separately.

Pointwise Halve, Add one, Negate, Square and Sine advance the preceding stage's exact checkpoint readings using the same kernel transformation that builds the expression. Cache these pure operations by operation and exact input value with a bounded capacity, so later blocks do not repeatedly evaluate earlier sine expressions. Find slope, Accumulate, Floor and Ceiling retain their full stage/domain evaluation. Reuse values only within the current checkpoint context; preserve exact target equality, complete expression simplification, node identities and acknowledged history. The placement benchmark includes 8.7 input and output edits in all three views and accepts a browser-engine selection.

For algebraic checkpoint comparisons, try certified outward rational intervals before general symbolic equality. Only strictly disjoint enclosures prove inequality; overlapping or unsupported enclosures retain the existing exact equality check. Include cold authored deep-link loads in WebKit performance checks. A transient worker failure during startup must keep the requested URL and saved workspace intact for Retry, including when the save already matches that URL; it must never silently replace placed blocks with a bare level or puzzle 1. Invalid input remains distinct from a failed evaluation.

All callers affected by one failed worker epoch share one replacement. Retiring an epoch clears its timers, rejects its boot and request waiters, detaches its handlers and terminates its worker, including after the final allowed retry. Preserve the last acknowledged construction; stale replies and failures cannot adopt state or start another recovery. Keep retained timing diagnostics bounded.

Continuous polynomial equations use the same bounded presentation cache as segmented equations. An edit must not fully simplify every unchanged recipe prefix again. Exact rational checkpoint and gap values are already reduced after substitution; render them directly. Performance checks include the ten-slot Height challenge, Undo/Redo and all three views, with math-worker timing separated from total edit latency; tiny introductory recipes alone miss this regression.
