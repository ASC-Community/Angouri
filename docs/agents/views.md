# Views

Mandatory contract from the [Angouri working guidance](../../AGENTS.md) whenever a change affects Flight, Equation or Flow presentation, naming, validation previews, mathematical notation or Full curve. Code paths are repository-relative. Kernel presentation-contract changes also require [kernel-exactness](kernel-exactness.md); sizing and scrolling are in [layout](layout.md); interactive changes also require [focus-keyboard](focus-keyboard.md).

## Product decisions

Give the views distinct jobs. Equation shows the ordered construction first and its fully AngouriMath-simplified form below (not merely InnerSimplified). Implicit recipes show the AngouriMath solutions for h below the construction, beside an exact position/expected/actual/match table; stack these sections on narrow screens. Omit the duplicate second formula when the forms agree. Its comparisons update immediately; Throw remains the action that awards completion. Flow explains each operation with aligned, equally scaled curve previews and a position slider. The slider chooses x; every stage shows height, or squared height for a squared-height recipe. Use h and h^2 in player-facing notation; do not introduce an auxiliary q function. Show the preceding curve and the height change, or the incoming tangent for a slope block. Include compact target coordinates and validation, with targets on the final graph. Use the kernel's samples and derivative stage, never a second frontend math evaluator. During a throw, the shared flight clock drives the slider and manual adjustment is disabled. Restore the last inspected position and enable the slider when playback finishes or is cancelled; preserve this position across view changes. Avoid duplicate target tables or another editor inside Flow.

Equation's comparison table keeps exact fractions prominent and gives non-integers a secondary KaTeX decimal to four significant digits, with trailing zeros removed. Use an equals sign when that displayed decimal represents the exact rational value, and an approximation sign only when it is rounded. Check this display relation with integer arithmetic, including negative values and scientific notation; floating-point equality cannot establish exactness. Integers need no duplicate decimal. These decimals are reading aids; equal rounded values must never turn an exact miss into a hit. Keep both values together in the same cell and fit ordinary puzzle comparisons at compact widths. At narrow widths, stack the equation and comparison sections within the available content area. Each section owns its overflow; keep the comparison header outside the scrolling rows. The height-gap row scrolls with the target readings. Center the equation group vertically within its own section when it fits, including when the duplicate simplified formula is hidden; overflowing content starts at the top.

Introduce a view through the question it answers. From authored puzzle 1.3 onward, keep the height-gap guide available through every chapter. Equation compares the signed difference between two named target positions separately from absolute heights; Flow names the same pair and uses blue brackets, direction arrows and exact per-stage gaps. Choose the positions of the lowest and highest required target heights using exact comparisons, retaining the first (leftmost) target on ties. Subtract the height at the low-target position from the height at the high-target position: 3.5 compares the height at x=1 minus the height at x=4, with target gap 9/8. Display these as heights evaluated at each position (h with an evaluation bar and x subscript), rather than introducing h(x) function notation. The target gap is max minus min among required heights; the current gap uses those same fixed positions and can be negative. Do not relabel it as the current curve's max minus min, which would erase reflection and move the reference points. Use the same notation in Equation, Flow, Notes and Hints. These are extrema among the required targets, not inferred extrema between them. Keep these positions fixed while the recipe changes, including when its current gap is negative; never recompute them from the player's curve. Start Flow's probe at the low-target position in Height to track fractional lifts. In later chapters, inspect whichever reference position is nearer the domain midpoint, retaining the midpoint if they are equally distant. A lift leaves a gap unchanged, a halve shrinks its magnitude, and reflection reverses its sign. The kernel's optional heightGuide supplies exact readings for authored explicit-height recipes from 1.3 onward, including squaring, derivative and integral stages. Parameter circles and paired-height equations use their own comparisons; do not subtract two ambiguous heights at the same position. It is not a target or extra success condition; a fitted gap can coexist with a missed puzzle. Create and shared challenges do not inherit this authored guide. Never compute a second exact evaluator in the frontend. Notes introduce comparing in Equation at 1.3, tracing fractional lifts in Flow at 1.4 and reconnect them at 1.5; 2.1 introduces the signed gap so it is familiar before 2.4. Keep the complete 1.5 reference on height differences, fractional lifts and view use in later puzzles and on return. Its puzzle-specific gap-first plan belongs in Hints. That is a planning order: a fractional final baseline can require interleaved lifts and halves, so hints must not imply that every halve precedes every lift.

Flight, Equation and Flow preview exact validation immediately with green checks and red crosses; Flight also distinguishes misses with dashed rings. Center Flight's checks and crosses within the targets, with light backing to separate the glyphs from the rings. Scale them with their targets; a fixed-size detached badge can outgrow its target on a small plot. Throw confirms the preview as it reaches each position: a filled green circle rewards a hit, and a red circle confirms a miss. Every view reads one shared flight clock. Switching views during a throw must retain its position and confirmed targets without restarting or awarding them again. Preserve the preview while awaiting confirmation, and reset filled badges after editing. Persist successful confirmation with the unchanged workspace. Restore Next/Rethrow only when that saved confirmation is explicit, the source remains complete in the current chapter record, and the kernel still reports the restored construction solved. A green preview or an old completion alone never substitutes for Throw. Accepted edits clear current confirmation; resuming it neither awards progress again nor replays a garden collection. Use the player-facing setting name "Skip animation"; it gives the same confirmed result immediately. Keep an explicit player override separate from the effective value: without an override, follow the live system reduced-motion preference, including changes during the session. View changes and autosaves must not turn an inherited default into a stored override. Existing explicit preferences retain their behavior.

The view is named Flight in the interface and `flight` in URLs, saved artifacts, the kernel contract and code. The earlier `world` name was replaced before production; do not add an alias for it.

The visible final-expression view is named Equation, covering both explicit heights and implicit circles. Preserve the stored `function` view identifier in URLs and artifacts for compatibility; earlier `equations` saves also import into this view without resetting the recipe. Display approximate decimal exponents as KaTeX multiplication by a power of ten, never JavaScript `e` notation, including symbolic comparisons and station readings.

## Interaction language

- A throw is deliberate and finite. The cucumber starts pulled behind stretched slingshot bands, releases, then follows the mathematical trajectory. Speed streaks follow the path tangent independently of the cucumber's tumble. The dotted line previews the current recipe; the solid trail shows travel. Target validation updates while editing; confirmation effects follow passage, and the last required hit reveals the enabled Next/Create action. Do not introduce gravity, collision tolerances, or a separate physics-based success rule.

## Visual consistency

Preserve Flow's horizontal and vertical inspection scroll through recipe edits, Undo/Redo and view switches. Reset it for an explicitly opened puzzle or imported construction. Reserve room for confirmation pulses inside scroll containers and keep Throw/Next icons the same size: validation must not introduce a transient scrollbar or resize the board. Check intermediate animation frames, not just the final layout.

Flight's required heights use KaTeX next to the targets, with light backing so the path cannot obscure the notation. Position labels toward the open middle of the plot and reserve their text gap in CSS pixels, keeping them clear of rings, the launcher and axis ticks as the diagram scales. The zero numeral must clear the first target's whole formula, not only its ring, at compact scales.

All mathematical notation uses KaTeX, including operation blocks, axes, coordinates, fractions, and samples. The current spatial puzzles display equations beginning h = ... or h^2 = ..., and dh/dx for slope. Time currently controls presentation. Future puzzles may use h(t) or x(t) when time or motion becomes part of their rules; choose notation by meaning, not a global naming preference. Display-only formula layout must not intercept input intended for neighboring controls.

## Implementation and verification

Keep zero in view in Flight, every Flow graph and every Notes sketch. Use a solid zero line distinct from the faint grid, labelled from 1.2 onward. Flight's height axis passes through the plotted x=0, using the same coordinate transform as the curve and targets. Offset the zero label for legibility, never the axis itself. Flight's baseline is neutral grey and extends beyond the endpoint targets; it must not look like another green trajectory or a connector between rings. Keep its height label left of the target and launcher at compact sizes. The minimal 1.1 landing retains the baseline and required-height labels while hiding axis annotations. Draw area shading behind the zero line. Positive-only, negative-only and lifted curves must not push this reference out of the plot.

Use upright differential d in both derivative and integral notation; variables stay italic. The kernel supplies the final function's exact initial slope. Project `(1, slope)` through Flight's coordinate map to aim the loaded cucumber and slingshot. Pull back and release along that same vector. Keep the loaded body rotation continuous through release, then ease into the airborne tumble. Speed lines follow the curve independently. Reserve room around the plot for steep pullbacks without covering axis labels or clipping the cucumber.

Each slope or signed-area visualization belongs inside the Flow card for its own derivative or integral operation. Place it to the left of that operation's output plot on wide layouts, and above the plot on narrow layouts: the input relationship leads into its mathematical output. Keep this order in the markup as well as the visual layout. Never prepend a detached station panel before Start. Read that operation's incoming and outgoing kernel stages; multiple calculus steps each have their own visualization and unique SVG resources. The slider and reward clock remain shared. Keep each compact Flow card inspectable through its local chain scroller, following [Viewport and scrolling](layout.md#viewport-and-scrolling); neither the relationship nor the launch action may be clipped. Spatial puzzles use height and slope, with an equal-unit local rise/run triangle, and height and signed area from zero. Do not label these velocity, motion or fluid flow: those require time to be part of the mathematical problem. Playback time only presents the construction.

## Extension direction

Circle Flow identifies target choices as Target 1, Target 2 and so on, alongside their exact coordinates; Create calls them points. Pair options name those same targets and repeat the selected coordinates beside the explanation. Keep every named target reachable under the compact-row rule in [Viewport and scrolling](layout.md#viewport-and-scrolling). Explain that the dashed segment joins the selected points, and any centre equally far from both lies on its blue perpendicular bisector. The current centre need not lie on that line. Comparing another pair narrows the possible centre. Keep the one-target distance calculation labelled with its inspected target so it cannot be mistaken for the pair calculation.

## Combined progression and exact extensions

Ordinary implicit solutions should fit whole. Use the kernel's complete height and condition lines; arrange the heights above a smaller domain line and show a shared condition once. Do not omit real-domain restrictions to shorten a formula, reconstruct branches in the frontend, or squeeze routine equations into an unreadable font. Large constructions can still scroll within their own formula section.

Dense paired targets keep their rings and centered verdicts proportional to the available spacing. Open authored recipe relations around their required targets and zero, rather than compressing the target shape to include a tall unfinished curve. Preserve this default frame through edits; the Full curve toggle includes the whole curve and targets and can restore that default frame. Indicate when the curve extends outside the default view. Create fits its curve. Place exact coordinate callouts in separate outside rows with subtle leaders; reserve enough room and verify that their rendered formulas do not overlap at narrow widths. Compute label layout only when rendering or resizing the scene, never during validation or playback.

## Critic review: phase, synthesis and compact play

Dense explicit Flight targets use whole coordinate labels in reserved rows with subtle leaders, never overlapping fractions or rings. Later explicit authored puzzles hold a target-focused frame through editing; Full curve temporarily includes the construction and restores the default frame when switched off. Zero stays visible. Measure labels on render/resize only; validation and playback do not relayout. Preserve the minimal landing and ordinary sparse labels.

Flow zero glyphs use HTML overlays projected through each graph’s SVG transform, including after narrow reflow and scrolling; never position KaTeX in foreignObject. In a squared-height recipe, calculus acts on the incoming right side: label its tangent d(h²)/dx and its D/I input as squared height. Sine’s projected output becomes h²; only the final Both heights card solves for ±h. Ordinary explicit recipes continue to label height.

## Curve transitions and player language

Full curve appears only when its next action changes the plotted projection. Compare actual coordinate transforms because differently stored bounds can still draw the same equal-scale view. Keep the return toggle while the full and default frames differ; when an edit or Undo makes them coincide, settle back to the default state and hide the redundant control. If it held keyboard focus, return focus to the selected view tab. Pending calculations mark it unavailable without discarding that focus; activation remains guarded. The Flight/Equation/Flow selector stays centred independently of Full curve. Keep the latter to its right on the same row, using its named icon at compact widths; do not shift the selector, overlap its controls or add another toolbar row.
