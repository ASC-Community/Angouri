# Community content

The community content has one editorial source: [the organization profile README](https://github.com/ASC-Community/.github/blob/main/profile/README.md). It combines the original profile and About page: introduction, Greek etymology, six projects, four contributor biographies and contribution information. About renders those same sections; `web/about/index.html` holds only the page shell. Branding, navigation and locally bundled icons remain website presentation.

Run `npm run sync:community` to refresh `content/community.json`. The snapshot records the upstream Git blob SHA and the unmodified Markdown; review and commit its diff with a release. Normal local builds render this snapshot without needing GitHub. The Pages workflow refreshes it before building, so an organization README change reaches the site on the next deployment. A README-only change can be published by manually running the Pages workflow on the default branch. There is no scheduled polling or automatic write back to the organization repository.

Edit shared content in `ASC-Community/.github/profile/README.md`, not in the snapshot or generated About HTML. Keep the logo heading and introductory paragraphs, followed by `## Projects`, `## People` and `## Contributions`. Each project uses a `###` heading, descriptive paragraph and repository link; each contributor uses a unique `###` heading and a biography that remains readable after Markdown sanitization. Headings alone, omitted images and raw HTML do not count as a biography. The sync and About renderer share this validation. A missing or incomplete section fails the refresh before writing, preserving the previous snapshot. This deliberately supports a one-way content flow; it does not scrape GitHub's rendered organization page.

`scripts/community.mjs` renders Markdown at build time. Raw HTML is excluded apart from the Greek language span; arbitrary remote images/badges are omitted from the website layout. Each project receives one consistent Shields GitHub-star badge generated from its parsed repository link. Badge counts load from Shields when the project is viewed; no GitHub API request or credential is needed in the game. Links may use HTTP, HTTPS or email; active protocols are rejected. Official project artwork is kept locally under `web/public/projects/`, with sources and licenses. New projects still render without an icon; add their official artwork when available. Honk# uses the current `ASC-Community/HonkSharp` repository link.

To review an upstream edit before pushing it, use `npm run sync:community -- --from <path/to/profile/README.md>`, build and inspect About. This stores the candidate's actual Git blob hash in the snapshot. After the authorized upstream push, run `npm run sync:community` normally and check that the hash matches the reviewed version. The preview command neither commits nor pushes content.

The website's GitHub button opens `ASC-Community/Angouri`, its configured push destination. Discord uses the existing site invite. Both are ordinary links opened by the player; no integration posts messages or needs credentials.

About uses static `tabindex="0"` on every link, including contents links and project badges, so WebKit's default keyboard setting and the no-JavaScript page retain native Tab order. It does not use the game's focus boundary. With JavaScript disabled, the game shows an in-viewport explanation and a keyboard-reachable route to About instead of unusable loading controls.

The organization profile uses the website wordmark, including the dotted cucumber. Run `npm run export:brand` after changing the wordmark. No site build or preview server is required: `scripts/brand-wordmark.mjs` generates the same outlined SVG for the website and exports, using the bundled KaTeX italic font, the reviewed geometry and `web/public/cucumber.svg`. Install the existing Playwright Chromium dependency with `npx playwright install chromium` if needed. The exporter writes light/dark SVGs and a font notice to `artifacts/branding/`, then uses Chromium to render fresh `angouri-light-preview.png` and `angouri-dark-preview.png` at 1800 × 600. Old previews are removed before SVG regeneration so a failed export cannot leave a stale image beside a changed SVG.

Review both fresh previews and the SVGs before copying the SVGs and notice to `.github/profile/branding/` in the organization repository. The dark variant changes only the lettering and dot color. No runtime fonts or external resources are required by either SVG, and preview rendering makes no network requests. About keeps its existing shared wordmark and omits this README-only image heading.
